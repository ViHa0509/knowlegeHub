They are written to scan linearly (bounded repeats, possessive quantifiers in the high_entropy lookahead; a 256 KiB adversarial string scans in < 1 s); unbounded `[A-Za-z0-9]*` lookaheads backtracked catastrophically on long tokens. Reads (`GET /v1/{ns}/redaction*`, `:scan`, `:verify`) need only a ns role; PUT/DELETE need ns admin. If-Match on selection is optional. `GET /v1/redaction/packs` stays person-only (spec: any signed-in person), so no auth rule was added. Vault canaries plug in via `redact.register_canary(fn)`; a canary hit emits `kh.canary_hit` from scrub.
- §6 items: `kind` must be a manifest type with `kind_of: item`; `key_sha` = sha256(canonical JSON `[keyspace, values]`)[:40]; text sha over lower-cased, whitespace-collapsed text. Propose adds one support row per provenance run (else the X-KH-Run / ''). Near-duplicate embeds the <=50 live candidates on the fly (no index needed). `updates` keeps kind/keyspace/key (else 422) and answers 201. Status events are `kh.item_status {item_id, from, to, reason}` (spec names only kh.item_promoted). When the confirm policy names roles/emails, only they (or ns admin) may activate/reopen; without, `items:confirm`. Admins bypass quorum votes. A named guard fails lint when `settings.items.guard_type` is unset or the records table is absent. `items:expire`/`:reindex` answer `{expired, item_ids}` / `{reindexed}`; `:support` needs `items:propose` or `items:write`; title > `KH_DISTILL_TITLE_CHARS` -> 422. Leak gate = `distill.leak(title+text, project)`.
- §6 retrieval: tiers need a query for meaning/log; `limit` caps each tier; dropped rows carry `reason` budget|cross_share; people rows count against `cross_share` (also `settings.retrieval.cross_share`). The rules tier reads `kh_rule`/`kh_rule_link` directly (entity_key/to_key = fold(entity)). `/worklog` answers 201 `{id, project, subject, ts}` and stores meta {knowledge_type quick, scope log, project, subject, topic, ts, author `ns:<ns>/<principal>`, ns, run_id, unit_id}. `/projects:match` on an ns without projects uses the caller's own projects (not the owner's) and answers `{best, ambiguous, weak_only, matches:[{project, term, on, weak, descriptor, aliases}]}`.
- §6 metrics: `POST /v1/{ns}/metrics` answers 200 `{accepted:[{index, series, ts_ms, unit_id, status created|duplicate|conflict, stored_value?}], created, duplicates, conflicts}`; a missing unit id is stored as "" (PK column). Unknown series -> 404 in reads, a per-index error in writes. Aggregate groups are `{key, n, sum, mean, sd}` (sample sd; n=1 -> 0); keys: day `YYYY-MM-DD`, week ISO `YYYY-Www`, baseline bool; `window` takes `7d|12h|30m|2w` (or plain days) and sets `from` when absent; the rollup source is used for day/week/project/baseline when from/to are day-aligned, else raw (<= 200 000 rows, `truncated: true` beyond). Compare: binary data = every value 0/1; `per_unit` averages each unit's values first; z sign is b - a. Rollback: control = latest obs of units never served the item (`pre_activation`: only those whose latest obs predates activation); fires when both n >= min_n; items are moved active -> contested -> withdrawn by conditional SQL on `kh_item` (status_reason `auto_rollback`, rev+1) unless the items module exposes `rollback_transition(c, ns, item_id, reason)`. The rollback lease (ns, `metrics_rollback`) held elsewhere -> 409 lease_held. Who may call it: admin or orchestrator.
- §6 outbox: subscriptions without `url` are pull-only (no outbox rows); `paused` subscriptions keep their cursor (backlog delivered on resume). Removing a subscription deletes its cursor/secret and turns its pending rows dead `unsubscribed`. KH secrets are `whsec_` + 32 random bytes (urlsafe b64); `GET .../secret` creates one when missing; a rotation emits `kh.secret_rotated`. Pull returns `{sub_id, events, next_after_seq, acked_seq}` (kinds filtered, type read ACL applied); ack beyond the stream end -> 422; ack lower than the stored cursor is a no-op. Retry of a non-dead delivery -> 409 invalid_transition. Delivery failures store `last_error` (`HTTP <status>`, `unsafe_target: ...`, `event_gone`, `secret_missing`); an unsafe target is dead at once. Metadata address 169.254.169.254 / fd00:ec2::254 and CGNAT 100.64/10 count as non-global.
- §6 lifecycle: export manifest.json carries `{format, ns, export_id, created_ms, include_vault, confirm_token, namespace (raw kh_ns row), modules {name: {version, migrations}}, files, kh_version}`; zip entries have a fixed 1980-01-01 timestamp; bytes columns are encoded `{"$b64": ...}`; vector metadata drops the store stamps (source_text, emb_*). Import (201) needs a clean id (absent, or a finished purge tombstone; else 409 duplicate), restores the ns as `active` (config `rebuild_pending` until rebuild, `imported_from`), writes `kh.ns_state` only to `_kh` (an event in the restored ns would break the byte-identical re-export), skips rows that collide on a KH-wide unique key (reported as `conflicts`, e.g. the ns client of the source ns) and tables unknown here (`skipped_tables`). Purge: no confirm and no force -> 428; wrong token -> 422 invalid; `force=true` is maintainer-only; `purge_after_ms` holds the purge start time while the state is `purged` (registry already reads that as "being purged"); the tombstone clears manifest/config. Retention: typed event kinds use the type's retention_days (null = keep); other kinds `retention.events_days` (default `KH_EVENTS_RETENTION_DAYS`); `_kh` and `KH_EVENTS_NS` use 180 d (prompts `KH_EVENTS_PROMPT_DAYS`). Global stop/resume answer `{stopped:[...]}` / `{resumed:[...]}` and emit `kh.ns_state` per ns plus `kh.agents_stop|resume` into `_kh`.
- §6 records: record view = `{type, id, project, rev, state, schema_ver, body, index, actor, created_ms, updated_ms}`; type must be a manifest type with `kind_of: record` (else 404); `kh.approval` (coord) is readable, never writable (403). `If-None-Match: *` also satisfies a `require_if_match` type; `If-Match` (incl. `*`) on a missing record answers 404. Without `?state` an update keeps the current state. Body size is checked before and after the body filters. Query: `state` accepts a value or list; null `eq/ne` -> IS [NOT] NULL; `id` is the order tie-breaker; `limit` default 100; `partition_by` groups the fetched page, `per_partition` (default 10, <= 500) caps the records kept per key (`weight_sum` = n without decay). Revisions list default 1000, newest first, `{type, id, current, revisions, count}`. Writes emit no kh.* events besides errors.
- §6 rules: values the spec leaves open: entity/attribute <= 512 chars, condition/effect <= 4000, quote_id/run_id <= 256; default origin `write_back`; rule_hash JSON is compact (`,`/`:` separators, unescaped UTF-8); links carry only AFFECTS/DEPENDS_ON (APPLIES_TO comes from the rule's own entity). PUT accepts `If-None-Match: *` (create-only; satisfies `require_if_match`). A PUT/bulk setting validity verified/contradicted without the confirm right -> 403. `:confirm` accepts validity verified|contradicted|unverified|retired (superseded only via PUT) and clears superseded_by. Bulk returns `{accepted:[{index, rule_id, outcome created|updated|duplicate}], rejected:[{index, errors}], created, duplicates, projection ok|stale|off}` (201 when something was created); re-asserting an existing rule (same id+content or same content) counts as duplicate and is marked in the run. Query: `hops` default 1 (one rule layer per hop), `min_confidence` drops rules without confidence, `entities` = `[{key, name, start}]`, `related` = reached entity keys that were not start entities, conflicts `{rule_ids, entity_key, attribute_key, overlap}`; `fallback_reason` = graph_off | projection_<state|missing> | graph_error: ...; the graph path takes entity->rule adjacency from the projection and reloads rules from SQL each hop. Scans: missing `scan_id` -> generated; replay answers 200; `request_sha` = sha256 of canonical `[project, sorted folded entities]`. Gate also returns `run_id, project, n_entities, n_rules`; `entities` are matched by folded key and `missing` lists the names as sent.
